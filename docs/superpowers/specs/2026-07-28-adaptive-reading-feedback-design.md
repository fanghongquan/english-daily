# 自适应阅读反馈闭环设计

## 目标

为每日英语阅读器增加一个低摩擦、移动端优先的难度反馈闭环。系统综合三级主观反馈、首次答题得分、阅读完成情况和网页内生词/短语操作数量，逐步估计个人阅读能力，并把稳定、有限幅度的难度参数提供给第二天的 DeepSeek 文章生成任务。

目标体验是“理解约 85%–90%，每篇遇到 5–8 个值得学习的新词”，不是持续提高难度。

## 费用约束

本功能必须保持零新增预算：

- 不购买腾讯云套餐、资源包或其他新云产品。
- 不创建新的 SCF 函数或 COS 存储桶，只复用现有函数和私有存储桶。
- 不增加 DeepSeek 调用次数，只在现有每日一次生成请求中增加一小段难度参数。
- 不使用 GitHub 大型 Runner、付费 Actions 存储或其他付费 GitHub 功能。
- 现有 SCF/COS 或档案读取不可用时降级到默认平衡档案，不自动开通、扩容或购买任何服务。
- 部署步骤只更新现有资源，并在变更前后检查是否出现购买、升级或计费确认页面；遇到这类页面立即停止。

## 已确认的产品决策

- 主观反馈使用三级：`有点简单 / 刚刚好 / 有点吃力`。
- 目标模式为平衡型：理解约 85%–90%，每篇 5–8 个新词。
- 难度调整综合主观和客观信号。
- 没有点击主观反馈时，仍使用客观数据做低权重调整。
- 保留每日 GitHub Actions 自动生成文章的模式，不改成手机端实时生成。
- 第一版不做复杂水平仪表盘，只显示一句近期趋势。
- 全程遵守零新增预算，不因个性化失败影响原有每日文章。

## 用户界面

反馈卡片位于阅读理解题之后，使用与现有阅读器一致的卡片、颜色和圆角，不弹窗打断阅读。

卡片包含：

- 标题：`这篇文章对你来说？`
- 三个至少 48px 高的按钮：`有点简单 / 刚刚好 / 有点吃力`
- 状态文本：
  - 同步成功：`已记录，将用于调整后续文章`
  - 本机待同步：`已保存在本机，联网后自动同步`
  - 趋势：`最近难度较合适，继续保持`、`后续会稍微提高难度` 或 `后续会稍微降低难度`

点击后的选择可以修改，后一次覆盖前一次。重复提交同一文章不会产生重复记录。

## 客户端数据

在现有 `englishDaily:progress:<date>` 进度对象中增加：

- `quizFirstScore`：第一次完成答题时的得分，重新作答不会覆盖。
- `wordActionCount`：本篇内不重复的单词操作数量。
- `phraseActionCount`：本篇内不重复的短语操作数量。
- `learningActionKeys`：仅保存在本机，用于避免同一词或短语重复计数；不上传。
- `difficultyFeedback`：`easy / balanced / hard / null`。
- `feedbackSyncState`：`pending / synced`。

上传负载只包含：

```json
{
  "op": "feedback_put",
  "article_date": "2026-07-28",
  "difficulty": "balanced",
  "completed": true,
  "quiz_first_score": 3,
  "quiz_total": 4,
  "word_action_count": 6,
  "phrase_action_count": 1
}
```

不上传具体单词、短语、文章正文或访问码。

## 同步行为

- 用户主动点击三级反馈时，允许沿用现有访问码提示并立即同步。
- 客观数据自动同步只在本机已经保存访问码时静默执行，不主动弹出访问码输入框。
- 网络、SCF 或 COS 失败时，将最新负载按文章日期写入本机待同步队列。
- 页面打开、答题完成、阅读完成或用户主动反馈时按日期串行补传整个队列；重试动作本身不会生成空白反馈。
- 同一日期有新负载时，旧请求成功后只有在本机待同步内容仍完全相同时才会删除，避免覆盖更新后的选择。
- 同一日期采用最后写入覆盖主观反馈；`completed` 只能从 `false` 变成 `true`；第一次答题得分一旦存在不再覆盖；操作数量取较大值。

## 云端存储

COS 使用两个私有对象：

- `learning-profile/events/<article_date>.json`：单篇合并后的反馈。
- `learning-profile/profile.json`：聚合学习档案和最近 7 篇信号。

学习档案结构：

```json
{
  "profile_version": 1,
  "target_mode": "balanced",
  "ability_score": 50.0,
  "base_score": 50.0,
  "observation_count": 0,
  "observed_dates": [],
  "target_words": 900,
  "target_new_words": 6,
  "sentence_level": 3,
  "target_comprehension": "85%-90%",
  "trend": "stable",
  "recent": [],
  "updated_at": "2026-07-28T00:00:00Z"
}
```

`observation_count` 记录历史上已接收过的不同文章日期数量，`observed_dates` 仅在私有档案中保留已处理日期，用于防止窗口滚动后重复累计。最近记录最多保留 7 篇；每条记录保存当时采用的步长。第 8 篇进入时，最旧信号折叠进 `base_score`，再根据剩余记录重算当前能力。更新最近 7 篇中的任意日期时，从 `base_score` 重放信号；更新已经折叠的旧日期时只把新旧信号差额应用一次。

## 难度算法

单篇信号范围为 `-1` 到 `1`，正数表示后续可以略难，负数表示后续应略简单。

权重：

- 主观反馈 50%：简单 `+1`，刚好 `0`，吃力 `-1`。
- 首次答题 25%：正确率 ≥85% 为 `+1`，60%–84% 为 `0`，<60% 为 `-1`。
- 生词/短语操作 20%：0–3 个偏简单，5–8 个刚好，>10 个偏难；边界数量采用半档信号。
- 阅读完成 5%：完成为轻微正向，未完成为轻微负向。

没有主观反馈时不重新分配其 50% 权重，因此客观数据只会产生低幅调整。前 3 篇属于校准期，能力调整步长减半。

每篇按信号小幅更新能力分，限制在 20–80。由能力分派生：

- `target_words`：700–1100，按 50 词取整。
- `target_new_words`：5–8。
- `sentence_level`：1–5。
- `trend`：最近加权信号大于 0.2 为 `harder`，小于 -0.2 为 `easier`，否则为 `stable`。

DeepSeek 只接收派生后的目标参数，不负责更新能力分。

## API 与鉴权

SCF 新增：

- `feedback_put`：浏览器 HMAC 鉴权，校验并合并反馈，返回更新后的简化档案。
- `profile_get`：供 GitHub Actions 使用服务器令牌读取档案。

浏览器继续使用 `APP_ACCESS_KEY` 和来源限制。GitHub Actions 使用独立的 `PROFILE_READ_TOKEN`，通过 `x-profile-token` 请求头访问 `profile_get`，不复用手机访问码。

`PROFILE_READ_TOKEN` 至少 32 字节，仅保存在腾讯云 SCF 环境变量和 GitHub Actions Secret。响应和日志不包含令牌、访问码或原始签名。

## 每日生成接入

新增 `profile_client.py`：

- 从 `PROFILE_API_URL` 读取档案。
- 使用 `PROFILE_READ_TOKEN` 请求头。
- 设置有限超时。
- 任何网络、鉴权、格式或服务错误都返回默认平衡档案，不阻断每日发布。

`get_article.py` 把以下约束加入提示词：

- 正文目标词数。
- 新词目标数量。
- 句子复杂度等级。
- 理解目标 85%–90%。
- 难度调整趋势。

GitHub Actions 将现有 `TTS_API_URL` 同时注入为 `PROFILE_API_URL`，并注入新的 `PROFILE_READ_TOKEN` Secret。

## 错误处理

- 客户端同步失败：保留本机 pending，不影响阅读和答题。
- COS 读取 404：使用初始平衡档案。
- COS 写入失败：返回 502，客户端稍后补传。
- COS 条件写冲突：使用 ETag 重新读取、合并并有限重试，避免多设备反馈互相覆盖。
- Actions 读取档案失败：记录不含秘密的警告，继续用默认参数生成。
- DeepSeek 未满足文章结构或字数：沿用现有生成校验与重试。
- 旧文章没有反馈组件状态：按默认空状态兼容，不迁移历史记录。

## 测试与验收

- 纯算法测试：权重、无主观反馈低权重、校准期、最近 7 篇、重复日期重算、目标上下限。
- SCF 测试：字段校验、浏览器鉴权、服务器鉴权、幂等合并、COS 404 和上游失败。
- 客户端契约测试：三级按钮、48px 触控、首次答题、本机队列、非交互同步不弹访问码、只上传计数。
- 生成测试：档案参数进入提示词；档案服务失败回退默认值。
- 工作流测试：注入 `PROFILE_API_URL` 和 `PROFILE_READ_TOKEN`。
- 全量单元测试、Python 编译、工作流 YAML 解析。
- 手机宽度浏览器验证完整的阅读、答题、反馈和同步状态。
- 发布后校验 GitHub Pages 新页面包含反馈组件，SCF 实际写入后 `profile_get` 能读回同一档案。
